# Site release

1. Check visible business claims against confirmed repository/Issue evidence. Flag unknown facts instead of inventing them.
2. Verify the relevant mobile and desktop layouts, navigation, services/tariffs presentation, typography and contact/CTA flow.
3. Check basic keyboard usability, labels/landmarks, images/alt text where applicable, titles/metadata and obvious performance issues.
4. Do not present generated demonstration imagery as real client work.
5. Run focused validation for the change, then repository lint/build before release.
6. Summarize remaining client inputs separately from technical defects so the owner knows what requires a business answer.
7. Use the independent project reviewer before a release PR is considered ready.
